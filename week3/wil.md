### 3. 정리

**1) Repository 계층**

- Repository(레포지토리)는 데이터베이스에 접근하여 CRUD를 수행하는 계층이다.  
  - Create : 데이터를 생성  
  - Read : 데이터를 조회  
  - Update : 기존 데이터 수정  
  - Delete : 데이터 삭제  
- 서비스 계층(Service Layer)은 반드시 Repository를 통해서만 DB에 접근하도록 설계한다.  
  Service → Repository → DB 구조로 작동한다.

---

**2) ORM과 JPA**

- 전통적인 데이터베이스 접근 방식은 **SQL을 직접 작성**해야 한다.  
  하지만 데이터베이스마다 SQL 문법이 다르고 DB가 바뀌면 코드를 모두 수정해야 해서 **비효율적이다**.
- 이를 해결하기 위해 등장한 표준 인터페이스가 **JDBC**이다.  
  → JDBC는 DB 종류에 상관없이 동일한 방식으로 코드 작성이 가능하도록 드라이버를 통해 SQL을 전달한다.
- 하지만 JDBC로 코드를 짜더라도 반복적인 SQL문 작성과  
  객체 ↔ 테이블 불일치(패러다임 불일치)라는 문제가 발생할 수 있다. 
  - CRUD 작업마다 SQL을 직접 작성해야 하고,  
  - 테이블 구조가 바뀌면 관련된 SQL을 모두 수정해야 하며,  
  - 객체와 테이블 간 개념이 달라 매핑 코드가 복잡해진다.
- 이런 문제를 해결하기 위해 등장한 기술이 **ORM**이다.  
  - ORM은 객체와 데이터베이스 테이블을 자동으로 매핑해주는 기술이다.  
  - 개발자는 SQL을 직접 작성하지 않아도, 객체를 저장하면 ORM이 자동으로 적절한 SQL을 생성한다.
- 자바 쪽의 ORM 기술 표준이 바로 **JPA**이다.  
  - JPA는 객체를 데이터베이스에 저장할 때, 직접 `INSERT`문을 작성하지 않아도  
    `em.persist(객체)`만 호출하면 SQL을 자동 생성하여 DB에 저장한다.  
  - 마치 컬렉션에 객체를 추가하는 것 처럼 DB에 데이터를 저장할 수 있다.

---

**3) JPA의 동작 방식**

- JPA의 중심에는 `EntityManager`가 있다. 
  - `EntityManager`는 엔티티 객체를 데이터베이스와 연결시켜주는 창구 역할을 한다.  
  - 이를 통해 SQL을 직접 작성하지 않고도 엔티티에 대한 CRUD 작업을 수행할 수 있다.  
  - `EntityManager`가 관리하는 엔티티 객체는 **영속성 컨텍스트**에 저장된다.

---

**(1) 영속성 컨텍스트란?**

- 영속성 컨텍스트는 JPA가 엔티티를 관리하기 위해 내부적으로 사용하는 가상의 저장소이다.  
- 특징
  1. **1차 캐시 역할**  
     - 한 번 조회한 엔티티를 내부에 저장해두고  
       동일한 엔티티를 다시 조회할 때는 DB를 거치지 않고 캐시에서 바로 반환한다.  
  2. **동일성 보장**  
     - 같은 트랜잭션 안에서는 같은 엔티티를 여러 번 조회해도 항상 같은 객체를 반환한다.  
  3. **쓰기 지연(Transactional Write-Behind)**  
     - 트랜잭션이 커밋될 때까지 `INSERT`, `UPDATE` SQL을 바로 실행하지 않고  
       일시적으로 모아두었다가 한 번에 DB에 반영한다.  
  4. **변경 감지(Dirty Checking)**  
     - 엔티티의 필드 값이 변경되면 JPA가 이를 감지하고  
       트랜잭션 커밋 시점에 자동으로 `UPDATE` 쿼리를 실행해 변경 내용을 반영한다.

---

**(2) 엔티티의 생명주기**

| 상태 | 설명 |
|------|------|
| **비영속 (New)** | 영속성 컨텍스트와 관련 없는 상태 |
| **영속 (Managed)** | `em.persist()`로 등록되어 컨텍스트에 의해 관리되는 상태 |
| **준영속 (Detached)** | 영속성 컨텍스트에서 분리된 상태 |
| **삭제 (Removed)** | 삭제 명령이 내려진 상태 (`em.remove()` 호출 시) |

---

**(3) 트랜잭션(Transaction)**

- 트랜잭션은 **데이터베이스 작업의 최소 단위**로  
  일련의 여러 작업을 하나의 묶음으로 처리하여 **모두 성공하면 커밋**하고  
  하나라도 실패하면 **롤백**한다.

**쓰기 지연 예시**
1. `em.persist(member)` 실행 → 엔티티가 영속성 컨텍스트에 저장됨 (아직 DB에는 반영 X)  
2. 여러 작업을 수행한 후, 모든 과정이 성공하면  
3. 트랜잭션이 커밋되며 JPA가 자동으로 `em.flush()` 실행  
4. SQL이 DB에 전송되어 실제 데이터 반영

**1차 캐시 예시**
1. 사용자가 DB에서 특정 엔티티를 조회하려고 함  
2. 영속성 컨텍스트에 없으면 DB에서 조회 후 캐시에 저장  
3. 동일한 엔티티를 다시 조회하면 DB를 거치지 않고 캐시에서 반환
